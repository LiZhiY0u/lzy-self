# lzy-self

将个人明确认可的协作要求、技术学习方式和工程判断方法整理为可加载的 Agent Skill。

本仓库的技能名称为 `lzy-self`。它帮助 AI 在技术讨论、学习指导、工程联调和复盘中遵循作者确认的工作方式。这里的“蒸馏”指从材料中提炼、核对和维护规则；当前版本是指令与参考文档，不涉及模型训练。

**当前阶段：规则与示例方案已由作者核对，结构检查通过；20 个行为测试用例尚未执行。**

[技能入口](lzy-self/SKILL.md) · [确认依据](lzy-self/references/confirmed-rules.md) · [测试方案](skill-tests/测试方案.md) · [测试结果](skill-tests/results.md)

## 使用边界

- 这是作者确认的协作与方法规则，不能充当作者的完整人格、当前经历或专业能力证明。
- 不将 AI 生成的代码、方案或评价归为作者独立完成的成果。
- 新技术的原理追溯按学习需要展开；熟悉技术和简单任务不强制套完整教学流程。
- 当前明确需求优先；某个项目的特殊要求只在该项目适用。
- 自主实现范围依据需求深度和复杂度判断。涉及组件版本更新、内核修改或敏感内容访问，须遵循已确认的讨论与授权边界；一般开发授权不能自动扩展为这些操作的授权。
- 使用 skill 不会自动开放工具或文件权限，也不代表作者授权访问私有数据或代其向外发言。
- 未执行的测试保持“未执行”；推荐方案和示例运行成功不等于实机验收通过。

本仓库没有收录原始聊天、本机绝对路径、会话标识或第三方关系资料。公开确认依据仅包含规则和相关脱敏案例。

## 安装与加载

### 前提

需要支持 Agent Skills 或允许读取本地技能文件的 AI 宿主。仅使用技能不需要 Python、依赖包或专用服务；运行结构检查需要已有的 Python 3。

本仓库按 Agent Skills 的 `SKILL.md` 结构组织。宿主的发现路径、工具权限和调用入口需要分别确认；当前没有完成所有宿主的兼容性测试。

### 在当前项目安装到 Codex

根据 [Codex 官方文档](https://learn.chatgpt.com/docs/build-skills)，项目级技能放入 `.agents/skills/`。请在目标项目根目录执行以下 PowerShell 命令：

```powershell
git clone https://github.com/LiZhiY0u/lzy-self.git lzy-self-source

$skillTarget = Join-Path (Get-Location) '.agents/skills/lzy-self'
if (Test-Path -LiteralPath $skillTarget) {
    throw '目标 skill 已存在，请先核对内容，避免覆盖。'
}
New-Item -ItemType Directory -Path '.agents/skills' -Force | Out-Null
Copy-Item -LiteralPath './lzy-self-source/lzy-self' -Destination $skillTarget -Recurse
```

复制后以 `$lzy-self` 显式调用。若宿主未显示新技能，按其官方说明刷新或重启。复制安装不会自动同步仓库后续更新；更新前应检查版本差异和本地定制。

已有源码时，只需将其中的 `lzy-self/` 文件夹复制到目标位置，不必再次克隆。

### 直接加载文件

尚未安装时，可以向允许读取项目文件的 AI 提供：

```text
请读取本项目 lzy-self/SKILL.md，按其中已确认的方法协助本次任务。
本次目标是：……
执行范围和约束是：……
```

文件是否被读取、规则是否生效，应以实际宿主记录和答复判断。仓库存在不等于自动加载成功。

## 验证与已知限制

| 验证项 | 状态 | 能证明什么 |
|---|---|---|
| 12 条规则及范围补充 | 作者逐条确认 | 本次整理的规则表述获得认可 |
| 3 个模拟场景方案 | 作者确认 | 学习、联调与方案交付的方法匹配 |
| 本地结构检查 | 通过 | 元数据、引用、用例字段、规则映射和结果记录一致 |
| 20 个行为用例 | 未执行 | 尚无行为通过率 |
| 自动发现与触发 | 未测试 | 不能声称宿主会正确自动选择该技能 |
| 独立上下文 / 不加载对照 | 未执行 | 不能声称比普通模型有已测量提升 |
| 实际硬件与学习迁移 | 未执行 | 不能声称真实工程或能力验收通过 |

用例包含 8 个关键项，覆盖 R01–R12、H01–H03、S01–S03，共 18 个登记规则组。**18/18 是用例与规则的映射覆盖，不是效果通过率，也不意味着覆盖所有未来情况。**

结构检查只使用 Python 标准库：

```powershell
python -X utf8 './skill-tests/check_suite.py'
```

它只检查当前草稿结构，不调用模型，不访问真实设备，不执行测试输入中的操作。当前清单均为未执行状态，脚本也检查结果字段没有伪造；开始正式行为评估后，应按实际状态维护校验逻辑。

官方 skill-creator 的 `quick_validate.py` 在作者环境因缺少 PyYAML 未运行，未为此安装额外依赖。本仓库提供的标准库检查与官方校验器不是同一工具，也不能验证模型实际行为。

行为评估时，只给被测会话技能和测试输入；判定标准由评估者保留。保存原始输出和必要动作证据，再逐项判定。关键失败不得被平均分掩盖。完整流程见 [测试方案](skill-tests/测试方案.md)。

一个待验证边界是：没有模拟器时，技能是否能利用现有工具继续排查，而不是过度阻塞。当前只列为风险假设，未声称已观察到该失败。

## 适用场景

| 场景 | 预期工作方式 |
|---|---|
| 未接触过的新技术 | 介绍技术 → 最小运行系统 → 构建原理与功能 → 示例优缺点 → 阅读或手动构建迁移检验 |
| 手动操作指导 | 说明环境、完整命令、作用与预期，根据实际输出分步推进 |
| MCU 与上位机联调 | 两端分别冒烟验证，再开展最小联调；提供案例、记录过程数据 |
| 方案选择 | 给出适用方案、推荐依据、优缺点、开发流程、实现细节及测试验收 |
| 项目复盘和进度说明 | 区分事实、推测、未知；过程和结果分别评价，保留问题与修正 |

文档和说明优先中文，保留准确的代码、命令、标识符及必要专业术语。

## 调用示例

下方是输入示例，不是已执行的效果演示或成功案例。

**新技术学习**

```text
$lzy-self
我第一次接触某项 MCU 技术。先给出第一轮学习安排，包含最小运行系统、
原理与功能解析、示例评价和迁移检验。先检查已有环境，不安装新工具。
```

**通信联调**

```text
$lzy-self
MCU 和上位机偶尔连接失败。请设计两端冒烟测试与最小联调用例，
说明所需协议资料，并提供过程数据记录模板。还没有测试结果。
```

**方案取舍**

```text
$lzy-self
请比较保持现有组件版本和升级版本两条路线，说明优缺点、开发流程、
实现细节与测试验收。升级前先讨论，暂不修改依赖。
```

## 规则维护

修改规则前，区分：

1. 作者明确确认的新要求。
2. 可重复观察到的任务行为。
3. 尚待确认的解释或推测。

提交变更应说明场景、证据、适用范围及对应测试。问题报告请使用最小脱敏材料，并注明宿主、模型、技能版本、输入、实际输出和预期行为。不要提交密钥、原始私有聊天、客户资料或设备身份信息。

对不同使用者，建议 fork 后替换个人偏好，并重新核对授权边界和测试；不能仅换名字就宣称生成了其个人分身。
