目前已知：MCU 与上位机间歇连接失败，暂无固定复现步骤。工具、版本、通信参数及协议帧均未知，尚不能判断故障发生在端口打开、数据传输、协议解析还是握手阶段。

以下为**未执行的测试案例与记录模板**。先补齐输入和预期，再按“单端冒烟 → 最小联调 → 重复与状态切换”推进；每次只改变一个条件。

### 测试前置条件

| 项目 | 待确认内容 |
|---|---|
| 硬件与链路 | MCU 型号、连接方式、转换器、线缆、供电、端口 |
| 软件版本 | MCU 固件标识、上位机版本、操作系统、驱动版本 |
| 测试工具 | 工具名称、版本、已确认可用的依据；模拟端版本 |
| 通信参数 | 按实际链路填写，例如波特率、校验、流控 |
| 协议输入 | 合法请求原始字节、发送顺序、帧边界、校验方式 |
| 预期输出 | 对应响应、状态变化、超时限值、连接成功判据 |
| 运行条件 | 启动顺序、重试策略、断开与恢复方式 |

未知字段填写“待确认”，不要填猜测值。若协议规定设备主动上报，应明确其触发条件，不默认由上位机先发送。

### 测试案例

| 编号 | 测试对象与步骤 | 预期与记录重点 |
|---|---|---|
| T01 | **MCU 单端冒烟**：用已确认可用的测试工具或模拟上位机，按协议完成一次最小交互 | MCU 接收、解析、响应满足协议；记录双向原始字节、时间戳及 MCU 状态 |
| T02 | **上位机单端冒烟**：用模拟设备返回已确认的合法响应 | 上位机正确发送请求、识别响应并进入规定状态；记录模拟端与上位机两侧日志 |
| T03 | **最小联调首次连接**：MCU 与真实上位机只执行连接所需的最少交互 | 各阶段按约定完成；记录端口打开、首个请求、首个响应、握手完成的时间 |
| T04 | **重复连接与断开**：保持环境不变，按正常操作重复 N 次，N 在执行前约定 | 每轮记录成功或失败、耗时、断开原因；失败后保留现场，不只记录最终重试成功 |
| T05 | **启动顺序切换**：分别测试 MCU 先启动、上位机先启动；其余条件固定 | 按设计等待或连接；记录两端启动时间、设备就绪时间与首次交互 |
| T06 | **状态切换**：分别测试上位机关闭重开、MCU 重启、链路断开恢复，每项独立执行 | 按设计释放资源、报告断开并恢复；记录残留状态、重试次数与恢复耗时 |
| T07 | **持续连接**：在预先约定的时长、报文类型和发送频率下运行 | 记录断连、超时、解析错误及最后一次有效交互；无故障只说明本次条件下未复现 |
| T08 | **异常响应与恢复**：通过模拟设备分别注入延迟响应、不响应等已定义情形 | 上位机按约定超时、报错或恢复；具体延迟、异常输入和预期必须先确认 |

T01、T02 分别验证两端；两者通过后再做 T03。单端失败时，先定位该端；单端通过也不能直接认定整体链路可靠。物理插拔或复位用例仅在设备允许的条件下执行。
