# 独立评分说明 A

本评分仅读取本轮 input-snapshot/cases.json 中 T01–T09 的 prompt、must、must_not，并对照本轮 T01-response.md 至 T09-response.md。未读取第一轮报告、其他评分或修改 skill。

判定规则：每条 must 必须有文本证据；must_not 的 met=true 表示所审文本中未出现该禁止行为。任一标准不足则整项 fail。不凭总体印象加分。结果为 7 pass、2 fail：T03、T05。

T03 存在标准解释歧义：回答充分解释了用途、组成、运行机制、取舍与迁移，但没有明确安排解释工程的构建过程。本评分没有要求必须教授编译工具链；明确安排解释从必要代码、初始化和工程配置到最小运行系统的构建关系，也可满足标准。“解析构建”若仅指最小系统组成/队列创建，则现有回答可以有 pass 的解释；本评分按严格证据门槛保留 fail，具体原因见 JSON notes。

T05 未提供最新文件尾 20 行命令。题目“还没有输出回传”与“分步指导”也存在两种解释：本评分要求本轮完整列出两项操作；另一种解释允许第一步后等待回传，因此缺少第二步不必判 fail。即便采用后者，回答只说无文件可能没有输出，没有明确的无文件处理步骤，仍不足以满足该必须项。本评分没有把等待回传本身作为禁止行为。

仅审文本回答，不将框架要求的回答存档计为模拟任务副作用。工具全轨迹未导出，故不得据本评分声称完成副作用审计；文本中的‘未执行’等表述只作为回答内容的证据。
